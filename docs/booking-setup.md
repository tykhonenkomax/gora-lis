# Календар бронювань Gora&Lis

## Одноразове підключення (для того, хто налаштовує сайт)

1. Створіть Supabase-проєкт. У SQL Editor виконайте `supabase/booking.sql` один раз. Скрипт створює таблиці, правила доступу й захист від накладання бронювань.
2. У **Authentication → Providers / Sign In → Email** увімкніть вхід поштою та паролем. Вимкніть публічну реєстрацію нових користувачів.
3. У **Authentication → Users → Add user → Create new user** створіть користувача з технічною адресою `admin@owners.gora-lis.invalid` та паролем, обов’язково підтвердьте email (**Auto Confirm**). Власник вводить на сайті лише логін **`admin`** і пароль; справжня пошта не потрібна. Для іншого логіна використовуйте адресу `<логін>@owners.gora-lis.invalid` (3–32 латинські літери, цифри, крапка, дефіс або підкреслення, нижній регістр). Пароль передайте власнику особисто, не записуйте його в репозиторій.
4. Скопіюйте UUID створеного користувача. У SQL Editor виконайте:

   ```sql
   insert into public.booking_admins (user_id)
   values ('UUID_КОРИСТУВАЧА');
   ```

   Самого входу в акаунт недостатньо: доступ до бронювань отримують лише користувачі цієї таблиці. Право додавати адміністраторів із браузера відсутнє.

5. У налаштуваннях проєкту знайдіть **Project URL** та **Publishable key** (`sb_publishable_…`; для старих проєктів підходить `anon` key).
6. Для локального запуску створіть `.env.local` за прикладом `.env.example`, заповніть URL і ключ. Перезапустіть `pnpm dev`.
7. Для GitHub Pages відкрийте **репозиторій → Settings → Secrets and variables → Actions → Variables** і додайте:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
8. Запустіть workflow **Deploy to GitHub Pages**. Vite вбудовує ці значення під час збірки, тому після зміни потрібен новий деплой.

Це публічний ключ для браузера. **Не використовуйте `service_role` / secret key** у `VITE_*`: вони обходять захист бази. Права забезпечуються RLS у SQL-скрипті.

## Адреси

- Сайт: `https://tykhonenkomax.github.io/gora-lis/?s=availability`
- Панель: `https://tykhonenkomax.github.io/gora-lis/admin`
- Локально: `http://localhost:5173/gora-lis/admin`

На GitHub Pages прямий вхід на `/admin` обробляється файлом `404.html`, як і сторінки будинків. Сервер може повертати статус 404, але застосунок відкриє панель.

## Як користуватися власнику

1. Відкрийте збережене посилання на панель і увійдіть.
2. Натисніть **Atmosfera** або **Panorama**.
3. Натисніть день **заїзду**, потім день **виїзду**. Дати також можна ввести в поля.
4. Оберіть **«❤️ Підтверджене»** або **«🌲 Попереднє»** та натисніть кнопку збереження. Дочекайтеся повідомлення «Збережено». Попереднє бронювання також тримає дати зайнятими; згодом натисніть **«Підтвердити ❤️»** у списку. Воно не скасовується автоматично.
5. Для скасування знайдіть бронювання у списку й натисніть **«Скасувати бронювання» → «Так, скасувати»**.

Сердечками позначаються **ночі**, а не весь день виїзду. Бронювання 10–12 числа займає ночі 10 і 11; нові гості можуть заїхати 12-го. Накладання не допускаються навіть при одночасній роботі з двох пристроїв.

Власник залишається авторизованим на своєму пристрої, доки сесія активна. На чужому пристрої потрібно натиснути «Вийти». Технічна адреса не отримує листів: якщо пароль забуто, той, хто налаштовує сайт, оновлює його в Supabase Authentication.

## Перевірка після підключення

- Увійти власником, додати бронювання Atmosfera на дві майбутні ночі. Перевірити дві позначки в іншому браузері без входу.
- Переконатися, що ті самі дати Panorama залишилися вільними.
- Додати сусіднє бронювання, що починається в день виїзду: воно має зберегтися.
- Спробувати накладання (також із двох відкритих панелей): база має відхилити друге бронювання.
- Скасувати бронювання й перевірити публічний календар. Він перечитує дані при зміні місяця/будинку, поверненні до вікна й раз на хвилину.
- Без входу спробувати запис до `reservations` і читання `booking_admins`: доступ має бути заборонений.
- Користувач без запису в `booking_admins` не повинен бачити/змінювати бронювання чи призначати собі права.
- Вимкнути інтернет: календар має повідомляти про недоступність даних, а не показувати всі дати вільними.

У базі зберігаються лише будинок і дати, без імен, телефонів і приватних нотаток. Форма заявки на сайті не створює бронювання автоматично: власник вносить його після підтвердження телефоном.

Без налаштованих параметрів календар показує «готується до запуску», а панель — пояснення про підключення. Демонстраційні бронювання не підмішуються до реальних даних.
